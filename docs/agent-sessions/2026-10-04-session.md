# Session 2026-10-04 — Frist-Trennung, Slot-Kapazität, Retro

## Goal

Vier Arbeitspakete: (1) getrennte Frist für Umbuchen/Stornieren gegenüber der Neubuchung, (2) Service-Slot-Kapazität (max. parallele Buchungen über alle Provider), (3) WhatsApp-Button-Größe prüfen, (4) Branches aufräumen. Danach Commit + Retro.

## Wichtige Implementations-Entscheidungen

- **Frist-Modell (nach Grilling korrigiert):** Umbuchen und Stornieren teilen sich **eine** „Umbuchungs-/Stornierungsfrist" (`manage_deadline_*`), getrennt von der Buchungsfrist. Drei Modi: `inherit` (Default — übernimmt die Buchungsfrist, bewahrt das heutige Verhalten), `minutes`, `fixed_time`. Nicht zwei unabhängige Fristen — der Salon unterscheidet nur „Neubuchung" vs. „Termin verwalten". Details in `docs/adr/0003-…`.
- **Slot-Kapazität:** pro Service eine Zahl (`slot_capacity`, 0 = unbegrenzt); zählt **Buchungen** (nicht Personen), Überlappung = Konflikt, über alle Provider, unabhängig von `attendants_number`. Nur Frontend. Bewusst **keine** gemeinsame Ressource über mehrere Services. Details in ADR 0003.
- **WhatsApp-Befund (widerspricht ursprünglicher Meldung):** Per Playwright gemessen — der schwebende Button ist auf der Buchungsseite **exakt gleich groß** wie auf der Hauptseite (48×48/SVG 24×24 @375px, 64×64/SVG 40×40 @1280px, Padding 12px). **Kein Fix nötig.** Die „größer"-Beobachtung war vermutlich ein gecachter Stand. → Kein CSS geändert.
